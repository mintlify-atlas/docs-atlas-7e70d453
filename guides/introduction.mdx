Scribe is a player data library for Roblox that handles persistence, replication, and type safety in one place. You describe your data once — a plain Lua table called a **template** — and Scribe turns every field into a typed accessor you can call from both the server and the client with no extra wiring. When a field changes on the server it streams to the client automatically; your UI just observes the value it needs.

## Why Scribe?

Every Roblox game that saves player progress faces the same set of problems: loading profiles without data loss, keeping UI in sync without a tangle of RemoteEvents, catching typos and wrong types before they corrupt a DataStore, and adding leaderboards or monetization without rewriting the data layer. Scribe solves all of these on top of ProfileStore's battle-tested session locking, so you get production-grade persistence from the start.

## Key Features

<CardGroup cols={2}>
  <Card title="Fully Typed Accessor Tree" icon="code">
    Scribe's new-type-solver-powered type functions generate a complete accessor tree from your template. Every call — `data.Coins.Increment(50)`, `data.Settings.Music.Get()`, `data.Inventory.Emberblade.Qty.Set(3)` — is checked at compile time against what you declared.
  </Card>
  <Card title="Automatic Replication" icon="arrows-rotate">
    Schema-compressed, batched diffs stream from server to client over a pluggable transport. Clients read data through the same API, with the same field names, and no RemoteEvents to wire up yourself.
  </Card>
  <Card title="ProfileStore Session Locking" icon="lock">
    Scribe wraps ProfileStore, which provides DataStore session locking to prevent concurrent writes from two servers corrupting a player's profile. Migrations, a wipe guard, GDPR export, and version history are built in.
  </Card>
  <Card title="Schemas All the Way Down" icon="layer-group">
    `Scribe.ArrayOf` and `Scribe.DictOf` give array and dictionary entries their own schema, so `data.Plots[1].Origin` is a typed `CFrame` that packs to 13 bytes with per-element bounds and size caps.
  </Card>
</CardGroup>

## What You Get Out of the Box

Scribe is more than a data layer. The core library ships with:

- **Leaderboards** — Declare which fields to rank and Scribe manages the OrderedDataStore, batched writes, and live snapshots.
- **Monetization** — Declare your products and passes; Scribe wires up `ProcessReceipt`, grants items fail-closed, and lets clients prompt purchases by name.
- **Gifting and Exchange** — Players can send items or currency to each other through a queued, auditable gift system, and two-sided item exchanges with atomic commit.
- **Transactions** — Atomic field updates with rollback, so a failed grant never leaves a player half-credited.
- **Diagnostics** — A structured log sink, load-phase tracking, anomaly detection, and health metrics.

## The New Luau Type Solver

Scribe's fully typed accessor tree is generated by Luau type functions, which require the **new Luau type solver**.

<Note>
  To enable it in Studio, select **Workspace** in the Explorer panel and set the `UseNewLuauTypeSolver` property to `Enabled`. In an external editor, enable the new solver in your Luau LSP settings.

  Scribe runs correctly without the new solver — all runtime behaviour is identical. Without it, `data.Coins` resolves to `any` instead of a typed accessor. `Data.Raw` is always available as an untyped escape hatch.
</Note>

## roblox-ts Support

Scribe ships a full TypeScript declaration package as `@rbxts/scribe`. It runs the same Luau implementation with inferred schema and API types. Five optional addon packages cover React, Vide, Fusion, telemetry, and leaderstats — all sharing the same Scribe version with no TypeScript runtime fork.

## Optional Add-ons

Additional modules live in the `addons/` folder and are copy-in or separate npm packages:

- **ScribeLeaderstats** — Keeps Roblox's player list synced with selected data paths.
- **ScribeTelemetry** — Posts Scribe health, failures, and summaries to Discord webhooks.
- **UI Bridges** — Drop-in adapters for Vide, React, and Fusion that turn any field into a reactive source.
