Some state belongs to the **server**, not to any player. The current wave number in a round, a boss's health bar, which map is loading, how many seconds remain on an intermission clock — every player sees the same value, nobody owns it, and none of it should ever be saved. The ServerStore gives you a place to declare that state exactly where it belongs, with the same typed accessors you use for player data.

## Declaring a ServerStore

`ServerStore` sits beside `Template` in your Scribe options. It takes the same declarators and produces one typed data tree for the whole server.

```lua
-- shared/GameData.luau
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Scribe = require(ReplicatedStorage.Packages.Scribe)

local template = {
    Coins = Scribe.Int(0, { Min = 0 }),
    Level = Scribe.Int(1, { Min = 1 }),
}

local serverStore = {
    Wave         = Scribe.Int(1, { Min = 1 }),
    BossHp       = Scribe.Int(0, { Min = 0 }),
    Intermission = Scribe.Number(0, { Min = 0 }),
}

return Scribe({
    Template          = template,
    ServerStore       = serverStore,
    ProfileStoreIndex = "PlayerData",
    ProfileKeyPrefix  = "PLAYER_",
})
```

That is the entire setup. The types for both the player data and the store are inferred automatically from their respective tables.

## Reading and Writing

On the server, `Data.ServerStore` holds the roots you declared. Every accessor works exactly as it does on a player's data tree.

```lua
-- server/GameLoop.server.luau
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Data = require(ReplicatedStorage.Shared.GameData).Server

-- Write store fields directly — no player argument needed.
Data.ServerStore.Wave.Increment(1)
Data.ServerStore.BossHp.Set(5000)

-- Subscribe to changes on the server.
Data.ServerStore.BossHp.Changed(function(hp)
    if hp <= 0 then
        endWave()
    end
end)
```

On the client, the same name appears on the same table and is read-only, just like the rest of the client mirror.

```lua
-- client/HUD.client.luau
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Data = require(ReplicatedStorage.Shared.GameData).Client

Data.ServerStore.Wave.Observe(function(wave)
    waveLabel.Text = `Wave {wave}`
end)
```

There is no player argument anywhere on either side. The store exists from the moment the bundle is built, so the server can write to it with nobody in the game yet.

<Tip>
  `Data.ServerStore.Wave.Set(7)` is a **single write** no matter how many players are connected. Scribe fans the resulting operation out to every ready client. The cost of a write grows with player count, but the state itself does not.
</Tip>

## Replication Behaviour

A player who joins during wave 7 receives `7` in the same `Init` snapshot that carries their own profile — there is no separate step. Store fields are replicated to all clients by default, exactly like `Shared` player fields.

<Note>
  A joining client receives the current store state as part of the initial handshake, so there is no gap between joining and seeing the correct values.
</Note>

## Keeping Fields Server-Only

To keep a store field on the server only — for example an RNG seed that clients must not read — declare it with `Scribe.ServerOnly`:

```lua
local serverStore = {
    Wave = Scribe.Int(1),
    Seed = Scribe.ServerOnly(0),   -- never replicated to clients
}
```

`Scribe.ServerOnly` is the only visibility modifier a store root accepts. `Scribe.Shared` is refused because a store root already reaches every client.

## Nothing in the Store Is Saved

A store root has no DataStore key behind it. It is not in any profile payload, it does not mark a profile dirty, and `Data.Flush` never sees it. When the server closes, the store goes with it.

That is a feature, not a limitation. Round state that outlived its round would be worse than useless. Anything that must survive a server restart — like a player's best wave — is ordinary template data on that player's profile.

## Practical Use Cases

<Tabs>
  <Tab title="Round State">
    Track wave number, boss health, and timer in the store. Every player's HUD reads them from the same replicated source.

    ```lua
    -- Start a new wave.
    Data.ServerStore.Wave.Set(currentWave)
    Data.ServerStore.BossHp.Set(bossMaxHp)
    Data.ServerStore.Intermission.Set(0)
    ```
  </Tab>
  <Tab title="World Announcements">
    Broadcast server-wide announcements without a separate RemoteEvent.

    ```lua
    local serverStore = {
        Announcement = Scribe.String("", { MaxLength = 200 }),
    }

    -- Server: push a message to every client.
    Data.ServerStore.Announcement.Set("Double coins active for 10 minutes!")

    -- Client: react to it.
    Data.ServerStore.Announcement.Observe(function(text)
        announcementBanner.Visible = text ~= ""
        announcementBanner.Text = text
    end)
    ```
  </Tab>
  <Tab title="Event Counters">
    Count server-wide events like total kills or chests opened.

    ```lua
    local serverStore = {
        TotalKills = Scribe.Int(0, { Min = 0 }),
    }

    -- Whenever any player gets a kill:
    Data.ServerStore.TotalKills.Increment(1)
    ```
  </Tab>
</Tabs>

## Naming Constraints

Player template roots and server store roots share one ID space, so a name can only appear in one of them. Scribe refuses the following at startup:

| Refused | Reason |
| --- | --- |
| A name already in `Template` | The two trees share one ID space |
| `Scribe.Session` | A store is never saved, so marking a field unsaved is redundant |
| `Scribe.Shared` | Every store root already reaches every client |
| `Scribe.Timed` | A deadline is swept per profile; the store has no profile |
| `Scribe.Dynamic` | The factory is sampled per profile load, which never happens here |
| A `_Scribe` prefix | Reserved for internal use |

Containers, records, `Scribe.Big`, bounds, and derived fields whose inputs stay within one side all work normally.

## Store Writes Inside Transactions

A store write from inside `Data.Transaction` is refused, because a rollback cannot undo a store write:

```lua
-- This aborts the transaction.
Data.Transaction(player, function()
    data.Coins.Increment(-100)
    Data.ServerStore.BossHp.Decrement(50)  -- refused
end)
```

Write to the store before the transaction, or after it returns `true`:

```lua
local ok = Data.Transaction(player, function()
    data.Coins.Increment(-100)
    data.Tickets.Increment(1)
end)

if ok then
    Data.ServerStore.BossHp.Decrement(50)
end
```

## Typed API Aliases

When you export named types for your data module, pass the player template first and the store template second:

```lua
-- shared/GameData.luau
local template = { Coins = Scribe.Int(0) }
local serverStore = {
    Wave = Scribe.Int(1),
    Seed = Scribe.ServerOnly(0),
}

local Data = Scribe({
    Template          = template,
    ServerStore       = serverStore,
    ProfileStoreIndex = "PlayerData",
    ProfileKeyPrefix  = "PLAYER_",
})

export type ServerData = Scribe.ServerData<typeof(template), typeof(serverStore)>
export type ClientData = Scribe.ClientData<typeof(template), typeof(serverStore)>

return Data
```

The `ServerData` type includes full read-write store accessors. The `ClientData` type includes read-only store accessors, with `ServerOnly` fields absent entirely.

## Performance

The store tree uses about 3 KB of memory and stays flat as roots are added — it is one tree for the whole server, so nothing about it scales with player count. A store field written every frame is cheaper than an equivalent RemoteEvent broadcast per player, because ops share a frame buffer with the rest of replication. A value that changes sixty times per second but is only read once per second should still only be written once per second.
