The Scribe API is split across five modules. Each one owns a distinct responsibility — template declaration and global helpers, server-side data management, client-side data access, per-field value methods, and exported types. This page explains how the reference is organized and what to look for before you follow a link to a specific method.

## Badge conventions

Every method listing carries one or more badges that tell you where and how to call it.

<CardGroup cols={2}>
  <Card title="server" icon="server">
    Call this only from a `Script` running on the server. Calling it from a `LocalScript` will error.
  </Card>
  <Card title="client" icon="monitor">
    Call this only from a `LocalScript`. Calling it from a `Script` will error.
  </Card>
  <Card title="yields" icon="clock">
    The calling thread may suspend before this function returns. Do not call it inside a non-yielding callback such as a `Changed` listener.
  </Card>
</CardGroup>

## Reading signatures

Scribe follows standard Luau annotation conventions throughout.

- A bare type such as `player: Player` is required.
- A trailing `?` such as `timeout: number?` marks an optional parameter — you may omit it or pass `nil`.
- Multiple return values are written as a tuple: `(boolean, string?)` means the first return is always a boolean and the second is an optional string.
- Generic type parameters appear as `<T>` and are usually inferred from context.

<Tip>
  Read the **return description** alongside the return type. A `boolean` return can mean different things for different methods — for example, `false` from `Server.Flush` does not mean data was lost, only that confirmation did not arrive in time.
</Tip>

## Naming conventions across the reference

The reference uses these conventions consistently:

- `PlayerData<T>` refers to the typed accessor tree returned by `Server.Get(player)`, `Server.WaitForData(player)`, and accessible directly as `Data.<fieldName>` on the client. Its field methods are documented on the [Value](/api/value) page.
- A `Disconnect` return is a zero-argument function. Call it to unsubscribe the listener.
- A `Signal` exposes `Connect`, `Once`, and `Wait`. Connections return a `Connection` object with a `Disconnect` method.
- Optional parameters with a `?` suffix have documented defaults where a default exists; omitting one is always safe.
