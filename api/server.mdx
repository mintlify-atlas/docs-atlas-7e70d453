The `Server` API is the `bundle.Server` half returned by `Scribe(options)`. It manages player profiles end-to-end: loading, saving, replication, monetization, leaderboards, exchanges, and server-to-server messaging. Index the object with a `Player` instance directly — `Data[player]` — to get that player's typed accessor tree.

<Note>
  All Server methods must be called from server-side `Script`s. Calling them from a `LocalScript` will error. Methods marked **yields** suspend the calling thread until they complete.
</Note>

---

## Player Data

### `Server.WaitForData(player, timeout?)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span> <span style={{fontSize:"0.75rem", background:"#7c3aed", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"4px"}}>yields</span>

Yields until the player's profile is `Ready`, then returns their accessor tree. On failure returns `(nil, reason)`. This is the safe way to read data in `PlayerAdded`.

```lua
local data, reason = Data.WaitForData(player, 60)
if not data then
    warn("Data unavailable:", reason)
    return
end
print(data.Coins.Get())
```

<ParamField body="player" type="Player" required>The player to wait for.</ParamField>
<ParamField body="timeout" type="number">Maximum seconds to wait. Default `60`.</ParamField>

<ResponseField name="data" type="PlayerData<T>?">
  The typed accessor tree, or `nil` on failure.
</ResponseField>
<ResponseField name="reason" type="LifecycleReason?">
  The failure reason when `data` is `nil`. See [`LifecycleReason`](/api/types#lifecyclereason).
</ResponseField>

---

### `Server.Get(player)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span>

Returns the player's accessor tree. **Errors if the profile is not `Ready`.** Prefer `WaitForData` on join; use this inside command handlers, which only run once the caller is `Ready`.

<ParamField body="player" type="Player" required></ParamField>
<ResponseField name="data" type="PlayerData<T>">The typed accessor tree.</ResponseField>

<Note>`Data[player]` is shorthand for `Data.Get(player)`. Both error if the profile is not Ready.</Note>

## Writes

### `Server.Batch(player, fn)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span>

Runs `fn` as a batch: every write inside coalesces into a single replication flush and one `Changed` pass per container.

```lua
Data.Batch(player, function()
    state.Index.Set(i + 1)
    state.StartedAt.Set(0)
    state.Current.Set(next)
end)
-- state.Changed fires ONCE with the end state
```

<ParamField body="player" type="Player" required></ParamField>
<ParamField body="fn" type="() -> ()" required>The write callback. Must not yield.</ParamField>

---

### `Server.Transaction(player, fn)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span>

Runs `fn` atomically. If it throws, every write inside is rolled back. On success returns `(true, nil)`.

```lua
local ok, err = Data.Transaction(player, function()
    data.Coins.Decrement(cost)
    data.Inventory.Insert({ Id = itemId })
end)
if not ok then warn("Transaction failed:", err) end
```

<ParamField body="player" type="Player" required></ParamField>
<ParamField body="fn" type="() -> ()" required>Must not yield. A yield is refused and rolled back.</ParamField>

<ResponseField name="ok" type="boolean">Whether the transaction committed.</ResponseField>
<ResponseField name="reason" type="string?">Error description on failure.</ResponseField>

<Warning>
  Atomic in memory only — `true` means writes landed on the player's tree, not that they are saved to disk. Pair with `Server.Flush` when durability is required before acknowledging.
</Warning>

## Persistence

### `Server.Flush(player, opts?)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span> <span style={{fontSize:"0.75rem", background:"#7c3aed", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"4px"}}>yields</span>

Saves the player's pending changes and waits for confirmation.

```lua
local saved = Data.Flush(player)
if not saved then
    warn("Save not confirmed; keep the operation pending")
end
```

<ParamField body="player" type="Player" required></ParamField>
<ParamField body="opts" type="{ Force: boolean?, Timeout: number? }">
  `Timeout` limits the confirmation wait in seconds (default `15`). `Force = true` bypasses the already-saved shortcut and a blocked wipe guard.
</ParamField>

<ResponseField name="boolean" type="boolean">
  `true` when the save is confirmed. `false` when confirmation did not arrive in time — a timed-out save can still finish later.
</ResponseField>

<ResponseField name="ok" type="boolean">`true` when the edit was saved.</ResponseField>
<ResponseField name="reason" type="string?">Explanation on failure.</ResponseField>
<ResponseField name="findings" type="{ { Path, Kind, Detail } }?">Validation violations, each with `Path`, `Kind`, and `Detail`.</ResponseField>

## Commands

### `Server.Command(name, specOrHandler, handler?)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span>

Registers a named command clients can call via `Client.Request`. Sender identity is always the real player. Args are shape-validated and rate-limited, and the handler only runs once the caller is `Ready`.

```lua
Data.Command("EquipItem", { Args = { "string" } }, function(player, itemId)
    if not Data[player].Inventory[itemId].Get() then return false, "not owned" end
    Data[player].Equipped.Set(itemId)
    return true
end)

Data.Command("CreateSaveSlot", {
    Args = { Scribe.Int(1, { Min = 1, Max = 4 }) },
}, function(player, slotNumber)
    -- slotNumber is an integer in [1, 4]; out-of-range was refused already
end)
```

<ParamField body="name" type="string" required>The command name clients pass to `Client.Request`.</ParamField>
<ParamField body="specOrHandler" type="{ Args: { any }?, Idempotent: boolean? } | handler" required>
  A spec table, or the handler function directly (spec defaults to no args). Each `Args` entry is a type string (`"string"`, `"number?"`), a Scribe declarator, or a shape table.
</ParamField>
<ParamField body="handler" type="(player: Player, ...any) -> ...any">
  The handler function. Omit when `specOrHandler` is already the handler.
</ParamField>

<Tip>
  `Idempotent = true` makes the command require a caller-supplied key sent with `Client.RequestOnce`. The handler runs at most once per key, and every repeat is answered with the original reply.
</Tip>

### `Server.Purchase(player, spec)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span>

```lua
local ok, reason = Data.Purchase(player, {

    ItemId = "Police01",
    Grant  = function(data) data.Vehicles.Insert("Police01") end,
})
```

<ParamField body="player" type="Player" required></ParamField>
<ParamField body="spec" type="PurchaseSpec" required>See [`PurchaseSpec`](/api/types#purchasespec).</ParamField>
<ResponseField name="ok" type="boolean"></ResponseField>
<ResponseField name="reason" type="string?">A [`PurchaseReason`](/api/types#purchasereason) string on failure.</ResponseField>

## Exchanges

The `Server.Exchange` sub-table provides the full player-to-player item exchange API.

### `Server.Exchange.Attempt(playerA, basketA, playerB, basketB)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span> <span style={{fontSize:"0.75rem", background:"#7c3aed", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"4px"}}>yields</span>

Exchanges two baskets between players on this server. Each basket lists what that player gives.

```lua
local outcome, why = Data.Exchange.Attempt(alice, {
    { Path = { "Inventory" }, Kind = "Key", Key = "Emberblade" },
    { Path = { "Coins" }, Kind = "Qty", Amount = 250 },
}, bob, {
    { Path = { "Inventory" }, Kind = "Key", Key = "Frostbrand" },
})
if outcome ~= "Committed" then
    return false, why
end
```

<ParamField body="playerA" type="Player" required></ParamField>
<ParamField body="basketA" type="{ ExchangeLeg }" required>What player A gives. See [`ExchangeLeg`](/api/types#exchangeleg).</ParamField>
<ParamField body="playerB" type="Player" required></ParamField>
<ParamField body="basketB" type="{ ExchangeLeg }" required>What player B gives.</ParamField>

<ResponseField name="outcome" type='"Committed" | "Aborted" | nil'>
  `"Committed"` means each basket is owed to the other player. `"Aborted"` means it is owed back to its original owner. `nil` means an early refusal or unknown verdict.
</ResponseField>
<ResponseField name="reason" type="string?">Explanation on refusal or `nil` outcome.</ResponseField>

---

## Messaging

### `Server.SendMessage(userId, message)` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span> <span style={{fontSize:"0.75rem", background:"#7c3aed", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"4px"}}>yields</span>

Sends a durable cross-server message to `userId`. Delivered to `Server.OnMessage` on whatever server they are (or next become) active on, including offline recipients. `message` must be DataStore-serializable.

<ParamField body="userId" type="number" required></ParamField>
<ParamField body="message" type="any" required>A DataStore-serializable value.</ParamField>
<ResponseField name="committed" type="boolean">`true` means committed, not delivered. `false` does not always mean nothing was written.</ResponseField>

<Warning>
  The queue is bounded at 1,000 undelivered messages per recipient. Delivery is at-least-once — handlers must be idempotent. Give each payload its own ID and ignore repeats.
</Warning>

## Signals

These signals are properties on the `Server` object, not methods. Connect with `:Connect(callback)`.

| Signal | Fires with | When |
|---|---|---|
| `Server.OnSave` | `{ Player, Ok, Duration, At }` | After each profile save |
| `Server.SessionEnded` | `(player, reason: LifecycleReason)` | When a session ends |
| `Server.OnAnomaly` | `{ Player, Path, Value, Reason }` | On data integrity events |
| `Server.OnGiftReceived` | `(player, { FromUserId, Product, GiftId })` | When a gift is delivered to a player |
| `Server.OnGiftCredit` | `(player, productName)` | When a gift credit is issued |
| `Server.OnOwnershipChanged` | `(player, key, owned)` | When ownership of a key changes |
| `Server.OnLeaderboard` | `(boardName, entries)` | When a leaderboard refreshes |
| `Server.OnCooldownEnded` | `(player, key)` | When a cooldown expires |

## Control

### `Server.Stop()` <span style={{fontSize:"0.75rem", background:"#2563eb", color:"white", borderRadius:"4px", padding:"2px 6px", marginLeft:"8px"}}>server</span>

Releases everything this bundle holds: the Timed sweep, leaderboard workers, replication flush, `Players` listeners, ProfileStore signal handlers, and `ProcessReceipt` if this bundle owns it. Idempotent. Does not save — call `Flush` first if the data matters.

<Note>
  A Scribe bundle normally lives for the server's lifetime. `Stop` exists for test suites and simulations that build many bundles.
</Note>

---

### `Server.Raw` — Server

The same API object without the typed accessor tree, for use when the type solver trips on your template.

---

### `Server.ProfileStore` — ProfileStore

The underlying ProfileStore instance. An advanced escape hatch for store-level operations Scribe does not wrap. Bypasses Scribe's schema, replication, and session guarantees — treat as read-mostly and never mutate an active-session profile through it.

---

### `Server.ServerStore` — table

The server-owned tree, one per server rather than per player. Present only when the bundle declares `ServerStore`. Each declared root is an accessor reached with no player argument, as in `Data.ServerStore.Wave.Set(3)`. Nothing in it is saved.
